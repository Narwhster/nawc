Workspace tools: tree, search, and prompt

File tree

The server returns a flat list of paths. buildTree synthesizes missing intermediate folders into nested maps, then materializes arrays with folders first and locale-sorted names. File labels omit the .html suffix. The active note automatically expands every ancestor folder.

Each row is keyboard-activatable and draggable. Folders reject a drop onto themselves or descendants. Moves are delegated to App, which handles collisions by opening a replace confirmation; contextual actions provide open/new/rename/delete operations.

Search

Command/control-K opens server-backed search over names, paths, and content. Requests wait 120 ms and use an AbortController, so stale queries cannot overwrite newer results. The shell increments revision for every filesystem event, causing an open query to run again. The server supplies matching terms; the client escapes them before building a case-insensitive highlighting expression. Command/control-Enter opens the selection in a new panel.

Agent composer

Completion is lexical and cursor-local: @ completes files, $ completes skills, a line-leading / completes commands, and /model switches to models. Paths containing whitespace or special characters are quoted and escaped. Before sending, collectPromptReferences parses and deduplicates file and skill references into structured inputs.

The panel asks separate endpoints for files, skills, commands, and models. Skill search ranks exact, prefix, substring, then subsequence matches. Built-in commands change local state: /plan and /default select mode, while /model leads into model completion. Other commands remain provider commands in the prompt.

Sending prefixes the text with the current note, includes structured references, mode, and optional model, then consumes double-newline-delimited server events from /api/prompt. Core-node “Ask the agent” ribbons use nawc:prompt to prefill and focus this composer.
