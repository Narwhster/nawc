Editor architecture

The UI is a three-column workbench: a file tree, a Dockview workspace containing one TipTap editor per open panel, and an agent prompt. App owns workspace-wide state; each DocumentPane owns loading and saving one note.

Shell and panels

App keeps the Dockview API in a ref and registers only one panel component, note. Opening normally reuses the active panel by replacing its path parameter; command/control-click creates a new panel with a random ID. This means navigation history belongs to a panel, not to a note.

Server-sent events from /api/events refresh the file listing and search index revision, then become a browser-level nawc:files-changed event. That event is the loose coupling between the shell and open documents or live source blocks.

A document pane fetches its path from /api/note, reloads when the matching file changes, and PUTs serialized HTML back. It translates editor navigation into the global nawc:open-note event.

Document model and persistence

The extension order is WikiLink, TipTap StarterKit, then every extension exposed by configured plugins. useEditor is keyed by note path, while later content changes are applied with emitUpdate: false so a server reload does not immediately save itself back. User edits schedule a save after 350 ms; later keystrokes cancel the prior timer.

Plugin node views need editor-only metadata, but files should contain native custom elements. Serialization finds every [data-nawc-node], recreates an element named by that marker, removes all data-nawc-* attributes, and preserves ordinary attributes. Interactive nodes are special: their source is restored as element children. Thus the stored form is <interactive>...</interactive>, not the editor representation.

Wiki links and history

Typing [[architecture/editor]] at the end of input creates an inline atomic node. It serializes as an anchor with data-wiki-link, displays the bracket syntax, and normalizes navigation by appending .html when absent. The parser also recognizes older/plain anchors whose entire text has bracket syntax.

Each panel has two mutable stacks. Ordinary navigation pushes the current path onto back and clears forward. Back/forward pops one stack and pushes the current path onto the other. Opening a historical destination in a new panel uses peekHistory, deliberately leaving the original history untouched. Renames and moves rewrite paths in both stacks and all open panel parameters.
