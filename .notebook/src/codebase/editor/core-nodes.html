Core plugin: rich nodes over plain HTML

The core plugin contributes three TipTap block nodes: interactive, ref, and runnable. All are atomic and draggable: TipTap treats each as one document unit while React node views supply their rich UI.

The server-side declaration names the client module, describes each custom element, and supplies an agent skill explaining the authoring syntax. The client default export registers the corresponding TipTap extensions.

Interactive prototypes

On parse, the custom element's inner HTML becomes a source attribute. InteractiveView renders that source through iframe srcDoc with sandbox="allow-scripts": scripts run, but without same-origin privileges. An edit dialog overlays a transparent textarea on highlighted HTML; synchronized scrolling keeps the highlighting aligned. Apply updates the TipTap node attribute, which triggers normal note saving.

Live source references

Both source nodes carry file, optional syntax, and optional declaration selectors name/type. The view POSTs these attributes to /api/source and renders the returned code plus exact start/end lines. Every filesystem event reloads it, so a note remains a live view rather than a pasted snapshot. The ribbon can jump to the source location, ask the agent about the block, or delete it.

Runnable references

Run mounts xterm and opens /api/run over WebSocket. The start message includes the selection and terminal dimensions. Subsequent messages carry terminal input, resizes, process output, or errors. A ResizeObserver fits the terminal; cleanup disposes subscriptions, closes the socket, and destroys xterm. Incrementing runId remounts the terminal for each run.

Highlighting

Explicit syntax wins over the file extension. Aliases normalize common forms such as tsx → typescript, html → xml, and sh → bash. A language is used only if this Highlight.js build knows it. Unknown text follows a small HTML escaper, preserving safety even though rendering uses dangerouslySetInnerHTML.

The persistence counterpart is [[codebase/editor/index]]: editor-only markers are stripped so these blocks remain readable custom elements on disk.
