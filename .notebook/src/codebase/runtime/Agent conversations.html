Agent conversations

NAWC treats a provider stream as an event log and the visible conversation as a projection. This is the boundary that keeps provider protocols out of React and prevents transport chunks from becoming accidental chat messages. 

provider session
  → normalized ProviderEvent stream
  → AgentManager lifecycle and in-memory projection
  → pure thread projection
  → message, activity, request, and plan UI

Contracts

Providers declare capabilities, modes, and typed per-model options; start or resume sessions; send turns; interrupt active work; and optionally answer interactive requests. References are typed: project file, skill, current note snapshot, or diagnostic. The server validates model option IDs and values against provider metadata before dispatch.

Projection

projectProviderEvent appends deltas to one assistant message, updates tool items by stable ID, resolves approvals, records plans and usage, and retains unknown events. It is pure apart from updating its supplied aggregate, so provider behavior is testable without HTTP or React.

Lifecycle and in-memory state

AgentManager owns active sessions, abort controllers, and the thread projection for the current server process. Threads are intentionally not written to the project or restored on startup, so restarting NAWC clears local conversation state. While the process is alive it passes the native thread ID back to providers and finishes interrupted or failed turns explicitly.

HTTP surface

The server exposes provider metadata, thread snapshots, turn streaming, interruption, deletion, and request responses. It resolves current-note content and validates file and skill references before a provider sees them.

Conversation UI

The panel composes message-scroller, message, bubble, attachment, and marker primitives with shadcn controls. Drafts and provider selections use browser storage, but conversation threads live only for the current server process. The current note is always visible as context, while @, $, slash completion, diagnostics, image paste/upload, stop, copy, model, reasoning, and provider modes remain available at the composer.
