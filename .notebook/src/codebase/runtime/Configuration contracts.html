Configuration contracts

@nawc/config is the shared type vocabulary between runtime and extension packages. defineConfig performs shallow Zod validation of the top-level shape and fills default VS Code editor and light theme values.

Syntax adapters

A NawcSyntax has a name, aliases, and resolve(source, selection). Resolution returns code plus original line boundaries. Optional run(request) makes selections executable by returning an argv array and cwd. syntaxFor centralizes name-or-alias selection for consumers.

Provider boundary

A NawcProvider must implement an async iterable prompt. Its small event union covers thread creation, text messages, command status, errors, and completion. Providers may also expose skills, models, and slash commands. Before calling a provider, the server validates models and selected references, resolves skill paths, and appends human-readable reference instructions to the prompt.

File references are relative to the provider working directory. Skill references carry both name and absolute SKILL.md path. Provider and plugin skills are merged for prompt discovery; disabled provider skills are omitted.

Editor and theme

An editor maps a validated local location to either a command argv or URL. The built-in VS Code adapter produces a vscode://file URL with optional line and column. launchEditor then chooses the platform URL launcher or spawns a configured command detached.

Themes are named light/dark CSS variable maps. Built-in light and dark themes supply the UI's semantic, sidebar, terminal, and syntax-highlight variables.

These contracts feed [[Runtime architecture]], while runnable syntax behavior continues in [[Run protocol]].
