Workspace and search

The workspace module is the runtime's trust boundary between browser-supplied paths and local files. Notebook operations are rooted at projectDir/src; source operations are rooted at configured baseDir.

Path safety

safePath rejects absolute paths and lexical traversal outside a root. safeExistingPath additionally resolves symbolic links on both target and root, rejecting a symlink whose real target escapes. Existing source and editor targets use the stronger form. Note creation uses safePath because the destination need not exist yet.

Notes and tree mutations

listNotes returns sorted recursive .html paths. listEntries also includes folders for the UI tree. Writes and renames create parent directories; new note names must end in .html. Entry moves can optionally replace a target, but forbid moving a folder inside itself.

Project file discovery

Prompt references come from git ls-files -co --exclude-standard: tracked files plus untracked, non-ignored files. Generated directory segments such as .git, .skills, dist, and node_modules are excluded. Results are cached for two seconds, and candidates are still passed through real-path validation. Directories are derived from file path prefixes.

This makes Git the definition of a selectable project file, not an unrestricted filesystem walk. A submitted prompt reference must appear in that candidate set and still exist safely beneath baseDir.

Source resolution

Without a syntax attribute, resolveSource returns the whole UTF-8 file and its line span. With syntax, it selects an adapter by canonical name or alias and delegates symbol/test extraction to its resolve function. A missing adapter or unresolved symbol is an error.

Search index

NoteSearchIndex parses each note as an HTML fragment, ignores text inside script and style, and indexes title, path, and visible text with MiniSearch. Titles receive the largest boost, then paths, then body text. Search uses AND combination, prefix matching, and modest fuzzy matching.

Filesystem events and API mutations invalidate the index. Rebuilds are coalesced through one promise; a revision counter ensures a change that occurs during a rebuild triggers another pass instead of publishing stale state as fresh.
