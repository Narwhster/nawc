Runtime architecture

The nawc package is the local runtime that joins a notebook directory, a Git-backed source tree, the React client, and an agent provider. Its public surface deliberately stays small: configuration helpers and createNawcServer.

Startup sequence

  1. The CLI reads --config and --port, using the current directory as the notebook project.
  2. loadConfig imports the TypeScript configuration through Jiti. The configured baseDir is resolved relative to the notebook project, while notes always live in projectDir/src.
  3. Startup rejects a base directory that is not within a Git repository, synchronizes plugin skills into .skills, and starts a Chokidar watcher for notes and referenced sources.
  4. Hono implements /api/*. A middleware-mode Vite server serves @nawc/ui for every other request. Both share one Node HTTP listener bound to 127.0.0.1.
  5. The port precedence is explicit CLI option, configured port, then 6292. SIGINT and SIGTERM close WebSockets, watcher, Vite, and HTTP server.

Server composition

createNawcServer owns almost all orchestration. It exposes metadata, note/file CRUD, search, source resolution, editor launching, prompt discovery and streaming, filesystem events, and runnable terminals. Provider skill and model discovery are lazily cached; a rejected lookup clears its cache so a later request can retry.

Client plugins are not bundled into the runtime ahead of time. The server resolves each configured plugin's client from the notebook project, then a Vite virtual module named virtual:nawc-plugins imports and exports them. React and React DOM are deduplicated so plugins share the UI's instances.

API map

  • /api/meta describes provider, editor, theme, base directory, and plugin nodes.
  • /api/notes, /api/files, /api/note, and folder/entry endpoints operate on notebook HTML.
  • /api/source resolves a source selection and adds its path to the watcher.
  • /api/prompt/* discovers files, skills, models and commands; /api/prompt streams provider events as SSE.
  • /api/events streams filesystem changes; /api/run is the WebSocket terminal protocol described in [[Run protocol]].
