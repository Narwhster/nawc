Skills and project creation

Plugin skill synchronization

At runtime startup, syncSkills materializes each configured plugin skill at .skills/<skill-name>/SKILL.md. Generated files carry a marker header. An existing file without that header is treated as user-owned and is never overwritten; generated content is replaced on each startup. The directory is returned to providers so agents can locate these skills.

Plugin skills and provider-native skills are presented together in the prompt picker, but retain their source metadata. Only plugin skills are copied into the notebook's .skills directory. See [[Configuration contracts]] for the provider skill shape.

The create-nawc scaffold

The creator CLI collects a target directory and package manager, supporting npm, pnpm, yarn, and Bun. Package-manager detection reads the leading name from npm_config_user_agent and defaults to npm. The generated package name is the normalized target directory basename.

createProject creates the directory but refuses to populate it unless it is empty. It writes:

  • a private ESM package with a nawc script and runtime, core, Codex provider, TypeScript syntax, and Vitest syntax dependencies;
  • nawc.config.ts with core plugin, Codex provider, both syntax adapters, VS Code, light theme, and baseDir: "..";
  • an interactive src/Welcome.html, README, and gitignore for dependencies and generated skills.

If installation is enabled, the selected manager runs install in the new project with inherited terminal output. The scaffold demonstrates the exact project shape consumed by [[Runtime architecture]].
