Run protocol

Runnable source nodes use a WebSocket at /api/run and a pseudo-terminal rather than a one-shot subprocess. This supports interactive input, terminal resizing, ANSI output, and process lifetime tied to the browser connection.

Client messages

  • start: a non-empty SourceSelection plus positive integer columns and rows.
  • input: arbitrary string data written to the PTY.
  • resize: positive integer columns and rows.

parseRunClientEvent treats JSON as untrusted data and returns undefined for malformed shapes. The connection closes with policy code 1008 for an invalid message. Dimensions are subsequently clamped to 1–500 columns and 1–200 rows.

Origin and execution checks

Upgrade requests are accepted only for the run path and when Origin exactly matches a localhost or 127.0.0.1 Host origin. This protects the local terminal endpoint from a page on another origin. The selected syntax must exist and implement run; the adapter returns an argv array and working directory. The server passes that argv directly to node-pty, with no shell interpolation, and sets an xterm-256color terminal environment.

Lifecycle details

Input and the latest resize received while the asynchronous start is pending are buffered, then applied once the PTY exists. PTY data becomes {type: "output", data}; exit becomes an exit event followed by a normal close. Startup failures become an error event and close code 1011. Closing the browser socket kills its child, and server shutdown closes every run socket.
