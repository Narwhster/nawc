Testing with runnable specifications

Runnable notes can hold executable acceptance examples close to a design without promoting every implementation-shaping preference into the permanent test suite.

Run a focused Vitest case

<runnable
  file="src/builder.spec.ts"
  syntax="vitest"
  name="builds the curried API"
  type="it"
></runnable>

The adapter finds an exact string-literal title. With the default it type it accepts either it(...) or test(...); another type matches that call name. Execution becomes vitest run FILE -t NAME.

Run a failing extensibility ticket

Ticket tests are real workspace tests. They are expected to fail until the corresponding issue is implemented.

Run a TypeScript example

The TypeScript adapter runs the selected file with Node and tsx. Keep examples deterministic, non-destructive, and fast. Runnable blocks always execute the file, not merely the displayed declaration selection.

For repository validation, vp test runs package tests and intentionally excludes the self-notebook. Run vp run notebook:test to execute the notebook's ticket tests and runnable specifications.
