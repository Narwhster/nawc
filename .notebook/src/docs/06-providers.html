06. Agent providers

A provider connects NAWC to the agent runtime that handles your conversations and edits. Choose one that is installed and authenticated on your machine, then set it in nawc.config.ts.

Built-in providers

  • codex() uses the Codex command-line app. Install and authenticate Codex, then add @nawc/provider-codex to the notebook.
  • opencode() uses OpenCode. Install and configure OpenCode, then add @nawc/provider-opencode.
  • cursor() uses Cursor's agent interface. Install and authenticate Cursor, then add @nawc/provider-cursor.

Choose a provider

import { opencode } from "@nawc/provider-opencode";

export default defineConfig({
  provider: opencode(),
  // ...the rest of your configuration
});

The provider package must be installed in the notebook before it can be imported. Restart NAWC after changing providers.

Provider options

Provider factories accept optional settings for the executable path, model, and reasoning effort. Codex also accepts a sandbox setting; OpenCode accepts a model-discovery timeout; Cursor accepts an API endpoint. For example: 

import { codex } from "@nawc/provider-codex";

provider: codex({
  model: "your-model-id",
  reasoningEffort: "medium",
  sandbox: "workspace-write",
})

If you omit model settings, the provider exposes the models and controls available from the runtime in the agent panel. If the panel cannot connect, check that the provider's command is on your PATH and that its own login or setup is complete.

Custom providers

A custom provider is an advanced extension for another agent service or local runtime. Use the provider package's documentation for its setup and supported settings rather than changing the notebook's other configuration.
