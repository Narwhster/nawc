06. Agent providers

A provider connects NAWC to the agent runtime that handles your conversations and edits. Choose one that is installed and authenticated on your machine, then set it in nawc.config.ts.

Choose a provider

Import the provider package's factory and pass it to defineConfig. The provider package must be installed in the notebook before it can be imported. Restart NAWC after changing providers.

import { codex } from "@nawc/provider-codex"; export default defineConfig({ provider: codex({ model: "your-model-id", reasoningEffort: "medium", sandbox: "workspace-write", }), // ...the rest of your configuration });

If you omit model settings, the provider exposes the models and controls available from the runtime in the agent panel. If the panel cannot connect, check that the provider's command is on your PATH and that its own login or setup is complete.

Built-in providers

codex

The codex() factory connects to the Codex command-line app. Install and authenticate Codex, then add @nawc/provider-codex to the notebook.

  • executable (string, default "codex") — Path to the Codex CLI binary.

  • model (string, runtime default) — Default model ID for conversations.

  • reasoningEffort (string, runtime default) — Default reasoning effort level.

  • sandbox ("read-only" | "workspace-write", default "workspace-write") — Restrict file access to read-only or allow workspace writes.

opencode

The opencode() factory connects to OpenCode. Install and configure OpenCode, then add @nawc/provider-opencode to the notebook.

  • executable (string, default "opencode") — Path to the OpenCode CLI binary.

  • model (string, runtime default) — Default model ID for conversations.

  • reasoningEffort (string, runtime default) — Default reasoning effort level.

  • serverTimeoutMs (number, default 5000) — Timeout in ms for OpenCode server startup.

cursor

The cursor() factory connects to Cursor's agent interface via the Agent Control Protocol (ACP). Install and authenticate Cursor, then add @nawc/provider-cursor to the notebook.

  • executable (string, default "agent" then "cursor-agent") — Path to the Cursor CLI binary; searched in order.

  • model (string, runtime default) — Default model ID for conversations.

  • reasoningEffort (string, runtime default) — Default reasoning effort level.

  • apiEndpoint (string, omitted by default) — Custom API endpoint URL (passed as -e to the CLI).

pi

The pi() factory connects to the Pi coding agent runtime. Install and authenticate Pi, then add @nawc/provider-pi to the notebook.

  • model (string, runtime default) — Default model ID (format: "provider/model").

  • reasoningEffort ("off" | "minimal" | "low" | "medium" | "high" | "xhigh", default "medium" for reasoning models else "off") — Default thinking level.

  • agentDir (string, omitted by default) — Directory containing Pi agent config (auth.json, models.json).

  • sessionDir (string, omitted by default) — Directory for persisting Pi sessions.

Creating your own provider

A provider is an object returned from a factory function. Import the types from @nawc/config and implement the parts your runtime needs.

Minimal provider

The simplest provider just needs a name and a prompt function. It receives the turn input and yields events back to the agent panel.

import type { NawcProvider, NawcProviderTurnInput, ProviderEvent } from "@nawc/config"; export function myProvider() { return { name: "my-provider", async *prompt(input: NawcProviderTurnInput): AsyncIterable { yield { type: "message.started", role: "assistant" }; yield { type: "message.delta", text: `Echo: ${input.prompt}` }; yield { type: "message.completed" }; yield { type: "turn.completed" }; }, } satisfies NawcProvider; }

Session-based provider

For stateful runtimes, implement startSession and sendTurn instead of prompt. This lets the panel reuse a session across multiple turns and interrupt it.

export function sessionProvider() { const sessions = new Map(); return { name: "session-provider", capabilities: ["attachments", "interrupt", "resume"], async startSession({ cwd, providerThreadId }) { const id = crypto.randomUUID(); sessions.set(id, new MySession(cwd, providerThreadId)); return { id, providerThreadId }; }, sendTurn(session, input) { return sessions.get(session.id)!.run(input); }, interrupt(session) { sessions.get(session.id)?.abort(); }, closeSession(session) { sessions.delete(session.id); }, } satisfies NawcProvider; }

Modes and models

Declare modes and let users pick a model and reasoning effort at runtime. Implement getSettings and listModels to surface available options.

export function configurableProvider() { return { name: "configurable-provider", modes: [ { id: "default", label: "Build", description: "Edit the workspace" }, { id: "plan", label: "Plan", description: "Propose changes without editing" }, ], getSettings: async () => ({ model: "my-model", reasoningEffort: "medium", }), listModels: async () => [ { id: "my-model", name: "My Model", contextWindow: 128_000, reasoningEfforts: [ { id: "low", description: "Low effort" }, { id: "medium", description: "Medium effort" }, ], defaultReasoningEffort: "medium", isDefault: true, }, ], } satisfies NawcProvider; }
