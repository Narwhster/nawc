Creating a provider

A provider connects the agent experience to a harness without coupling the server or React UI to that harness. Implement NawcProvider, open a session, and translate native activity into normalized events.

startSession restores a provider thread when one is known. sendTurn streams message deltas, tool lifecycle, plans, requests, warnings, errors, and completion. Stable item IDs let NAWC update one message or activity instead of rendering each transport event as a new bubble. Unknown native events remain available in the saved projection for diagnostics.

Declare capabilities rather than relying on provider names

Providers describe resume, interrupt, interactive request, attachment, and in-session model switching support. They also supply modes, models, typed model options, skills, and commands. The agent panel renders those descriptions and forwards validated selections; it does not special-case Codex. A speed tier such as Codex Fast is a model option rather than a fake slash command.

Codex as a worked example

The Codex adapter invokes codex exec --json for the first turn and codex exec resume thereafter. It translates messages and tool activity, preserves unknown events, supplies typed note/file/skill/diagnostic context, and interrupts the active process on request. Plan and review modes force read-only sandboxing.

Prefer argv-based process APIs, preserve provider errors as visible error events, and never interpret prompt text as a shell command.
