01. The NAWC workflow

Everything in these docs was generated using the nawc skills.

If I'm honest it's mostly because I was too lazy to write the docs myself.

NAWC uses a "diffusion workflow". A rough idea gradually spreads into a durable note, recorded decisions, prototypes, runnable examples, tests, and focused implementation tickets. This keeps your preferences and intent available to the agents that work on the project later, instead of compressing them into one plain-text issue.

Start with an idea

Create a note and describe what you want in whatever form is useful: a sketch, a problem, a preference, or an incomplete feature idea. You do not need to know the final design before you begin. The note is a shared workspace for discovering it.

Step 1 - Refine the idea

  1. Ask the agent to refine. It asks one blocking question at a time and records your answers as design decisions. If your first idea changes as you think through the questions, update it. Reworking the idea is part of the workflow, not a failure of the original request.

  2. Review the evidence. The agent turns important decisions into artifacts such as interactive prototypes, runnable examples, and tests. Use these artifacts to react to the evolving idea, answer more questions, and redirect the design until it represents what you want.

  3. Let the plan diffuse into tickets. Once the intent is clear, the agent records the dependencies and breaks the plan into focused implementation tickets when necessary. Each ticket carries the decisions and evidence that led to it, so another agent can work from the same context.

Step 2 - Implement the result

When a ticket is ready, use implement. The agent follows the recorded decisions, changes the code or notes, and runs the relevant checks.

The short version is: rough idea -> refine <-> decisions and evidence -> ready ticket -> implement

Other skills

The nawc skill gives the agent the notebook vocabulary: interactive prototypes, live source references, runnable examples, wiki links, and the notes that connect decisions and evidence to the codebase.

The other skills from nawcSkills support the workflow. orient recovers context, probe creates evidence, split separates independent goals, ticket-ready checks readiness, and review-implementation checks the result. You do not need to invoke them directly.

Other plugins can add their own skills for languages, test frameworks, and other tools. For example, typescript and vitest tell the agent which syntax names, selectors, and runner behavior are valid for code references and runnable examples. You do not need to invoke these directly either.
