Creating a plugin

A plugin has two halves: server-readable metadata and a browser client module. The server definition names the plugin, points to the client module, and may advertise custom nodes and generated agent skills.

The package must make the client specifier resolvable from the notebook project. At startup NAWC resolves every configured client, generates a Vite virtual module, and loads the resulting client plugins into the editor.

Client module

Export a NawcClientPlugin: a name and an array of Tiptap extensions. A custom element normally needs a Tiptap node that defines parsing, rendering, attributes, and (when useful) a React node view.

The core plugin is the reference implementation: its server entry declares nodes and a skill, while its client implements editor rendering for interactive, ref, and runnable.

Add the plugin instance to plugins in nawc.config.ts. Skill synchronization refuses to overwrite an existing unmarked SKILL.md, so generated skills do not silently take ownership of user files.
