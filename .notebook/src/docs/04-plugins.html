04. Plugins

Plugins add capabilities to a notebook. Enable the plugins you need in the plugins array in nawc.config.ts.

First-party plugins

  • core() adds <code>, <runnable>, and <interactive> note elements. Most notebooks should enable it.

  • nawcSkills() gives your configured agent the NAWC workflow and note-writing skills. Enable it when you want the agent to work with the recommended NAWC workflow. This plugin is separate to the core plugin in case you want to write your own skills instead.

  • typescript() adds TypeScript and TSX source selection and execution.

  • vitest() adds syntax support for Vitest tests.

  • react() adds React component preview and rendering.

  • tailwind() adds Tailwind CSS support.

  • java() adds Java syntax support.

  • junit() adds JUnit test syntax support.

  • rust() adds Rust syntax support.

  • tldraw() adds tldraw support.

Enable a plugin

import { core } from "@nawc/core"; import { nawcSkills } from "@nawc/nawc-skills"; import { typescript } from "@nawc/syntax-typescript"; import { vitest } from "@nawc/syntax-vitest"; import { react } from "@nawc/react"; import { tailwind } from "@nawc/tailwind"; import { java } from "@nawc/syntax-java"; import { junit } from "@nawc/syntax-junit"; import { rust } from "@nawc/syntax-rust"; import { tldraw } from "@nawc/tldraw"; export default defineConfig({ plugins: [ core(), nawcSkills(), typescript(), vitest(), react(), tailwind(), java(), junit(), rust(), tldraw(), ], // ...the rest of your configuration });

Add the package to the notebook first, then add its factory to the array. Restart NAWC after changing the configuration so the new note elements and skills are loaded.

Writing your own plugin

A plugin is an object returned from a factory function. Import definePlugin from @nawc/plugin and pick the capabilities you need.

Note elements

Register custom HTML tags that appear in the editor. Each tag needs a client-side tiptap extension to parse and render it.

import { definePlugin } from "@nawc/plugin"; export function myPlugin() { return definePlugin({ name: "my-plugin", client: "my-plugin/client", nodes: [ { name: "my-widget", tag: "my-widget", description: "A custom widget" }, ], }); }

Syntax adapters

Add a new source language. The resolve function extracts a named region from source. The optional run function produces a shell command.

import { definePlugin } from "@nawc/plugin"; export function myLang() { return definePlugin({ name: "my-lang", syntax: [ { name: "my-lang", aliases: [], highlight: "my-lang", extension: "ml", resolve(source, selection) { // Return the matched source region or undefined. return undefined; }, run({ file, cwd }) { return { command: ["my-interpreter", file], cwd }; }, }, ], }); }

Skills

Provide YAML-frontmatter markdown that gets synced to .skills/<name>/SKILL.md at startup.

import { definePlugin } from "@nawc/plugin"; const skill = `--- name: my-skill description: Use when doing X. --- Instructions for the agent go here.`; export function myPlugin() { return definePlugin({ name: "my-plugin", skills: [{ name: "my-skill", content: skill }], }); }

Vite integration

Inject Vite plugins into the dev server. The callback receives the resolved baseDir.

import { definePlugin } from "@nawc/plugin"; export function myPlugin() { return definePlugin({ name: "my-plugin", vite: ({ baseDir }) => myVitePlugin(baseDir), }); }

File references

Parse a note's HTML to extract file paths for nawc splash.

import { definePlugin } from "@nawc/plugin"; export function myPlugin() { return definePlugin({ name: "my-plugin", references({ html }) { // Return [{ path: "src/foo.ts" }, ...] return []; }, }); }

Continue with [[docs/05-syntax]] to use source references and runnable examples.
