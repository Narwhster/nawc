Providers and event streams

The provider contract is an anti-corruption layer around an agent harness. NAWC does not need to understand Codex JSONL, subprocess details, or app-server pagination; it consumes a stable async stream. 

agent-specific output
  → provider parser
  → normalized session / turn / message / tool / request events
  → durable thread projection
  → NAWC conversation interface

Codex uses two integration paths. First-turn execution uses codex exec --json and follow-ups use codex exec resume. Skills and models use short-lived JSON-RPC app-server requests; model listing follows cursors and filters hidden entries. The adapter caches neither—the NAWC server owns request-level caching and retries failed listings on the next request.

Plan and review modes are semantic as well as mechanical: they select read-only sandboxing. See [[Creating a provider]], [[Agent conversations]], and [[Safe notebook workflows]].
