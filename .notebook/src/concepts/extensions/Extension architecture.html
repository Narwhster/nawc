Extension architecture

NAWC separates four decisions that often get tangled in developer tools: what the editor understands, which agent receives prompts, how source is selected or executed, and how the notebook is composed.

Plugin
Tiptap extensions, node metadata, skills
Provider
prompt → normalized event stream
Syntax
selection → source / argv
NAWC server + config
resolves modules, enforces paths, serves editor, launches trusted commands

Plugins cross the server/browser boundary: the server reads metadata and synchronizes skills, while Vite loads the client module into the editor. Providers cross the agent-process boundary by translating harness-specific output into five event variants. Syntax adapters cross the source/process boundary by resolving a selection and optionally returning a command.

The contracts live in [[Configuration internals]]. Practical entry points are [[Creating a plugin]], [[Creating a provider]], and [[Creating a syntax adapter]].
