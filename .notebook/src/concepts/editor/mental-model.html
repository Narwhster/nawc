The editor's mental model

A NAWC note has three forms, each optimized for a different job:

  1. HTML on disk is portable, diffable, and agent-editable.
  2. A TipTap document gives structure, selection, input rules, and plugin extension points.
  3. React node views turn selected custom elements into live tools such as prototypes, source viewers, and terminals.

Why the browser events matter

The shell, document editor, plugin blocks, and prompt are not wired through one enormous React state tree. Small browser events form a local protocol: nawc:open-note requests navigation, nawc:files-changed invalidates live content, and nawc:prompt seeds the agent composer. Server-sent filesystem events enter at the shell and fan out through that protocol.

Design consequences

  • A plugin can extend editing without inventing a new file format.
  • Moving a note requires updating panel state and navigation history, not rewriting the note.
  • Live references deliberately trade static snapshots for fidelity to current code.
  • Interactive HTML is isolated in a sandbox, but it is still active content and should be authored intentionally.
  • Autosave is eventual (350 ms), so the in-memory editor briefly leads the disk file.
