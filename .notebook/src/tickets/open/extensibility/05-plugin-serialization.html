Move custom-node serialization into plugins

Issue

The browser plugin contract lets plugins add Tiptap extensions, but serialization has a NAWC-level special case for the core plugin's interactive node. A plugin that stores editor-only state in attributes cannot register its own conversion back to canonical note HTML.

Current behavior

Editor serializes every update through serializeNote and serializeHtml. The serializer converts every element marked data-nawc-node into an element named by that marker, strips internal attributes, and only restores child HTML when kind === "interactive". The core plugin creates that marker and source attribute in Interactive.renderHTML.

Prototype

A serializer pipeline gives each plugin a chance to turn its editor representation into persisted HTML.
