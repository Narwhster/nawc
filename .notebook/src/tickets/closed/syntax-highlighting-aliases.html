Resolve highlighting from configured syntax aliases

Issue

Even when a custom syntax has a valid alias for source extraction, the same alias is not shared with the highlighter. This creates a split contract: syntax="diagram" may resolve through the server, while the browser independently decides whether diagram is a language known to Highlight.js.

Current behavior

syntaxFor and resolveSource match canonical names and configured aliases. The core plugin's sourceLanguage instead checks its local languageAliases map and then hljs.getLanguage; neither function receives the configured syntax list. The existing tests only cover built-in aliases such as ts, vitest, and file extensions.

Prototype

The adapter registry should be the source of truth for alias lookup; a syntax can then return a renderer or highlighting language.
