02-agent-panel-sucks

Issues

  1. There's a new thread for every prompt.

  2. The message doesn't actually get "sent".

  3. The agent's responses get displayed weirdly. As if they're multiple messages.

  4. We're still not properly loading commands from the agent (codex for example, also has /fast, and a lot more)

Shadcn has some great AI/chat-related components exactly for this.

Resolution

Replaced the stateless prompt renderer with durable provider sessions, a normalized conversation projection, persisted history and drafts, grouped messages and activity, interruption, provider controls (including typed options such as Codex Fast), image attachments, and typed context. See [[codebase/runtime/Agent conversations]] and [[Using the agent panel]].

A newly created first conversation is inserted into the local projection before it is selected, so the stale-thread guard cannot clear the selection while the first turn starts. The component regression test covers creation from an empty history through the real send control.
