Make provider event rendering extensible

Issue

Provider events are a closed union and the prompt panel knows only how to display messages, errors, and command strings. Provider-specific progress, tool calls, approvals, citations, or structured output either cannot satisfy the type contract or are reduced to the event type name.

Current behavior

ProviderEvent defines thread-started, message, command, error, and done variants. The server forwards events unchanged over SSE, but PromptPanel renders event.text, event.message, or a command/status string and otherwise falls back to event.type. The provider has no renderer registration or opaque payload channel in the public contract.

Prototype

An event renderer registry can preserve provider payloads while letting the provider or plugin supply presentation.

Resolution

Common message, tool, plan, request, warning, error, and lifecycle semantics are normalized. Every event may retain an opaque payload, and unknown native events are persisted instead of discarded.
