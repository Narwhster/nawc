Let providers define prompt modes

Issue

The provider contract exposes only two prompt modes, and the UI hard-codes their labels and behavior. A provider that supports review, explain, draft, or another mode cannot describe that mode to the prompt panel or receive a typed mode identifier without changing NAWC itself.

Current behavior

NawcProvider.prompt accepts mode?: "default" | "plan". The server rejects every other value, while PromptPanel injects plan and default into the slash-command list and changes local state for those exact strings. The Codex provider maps only plan to a read-only sandbox and ignores any provider-defined mode concept.

Prototype

Modes can be provider metadata with an ID and display information, while the UI forwards the selected ID without interpreting it.

Resolution

Providers now publish mode IDs, labels, and descriptions. The panel renders that metadata and forwards the selected ID without interpreting it; the provider adapter owns its semantics.
