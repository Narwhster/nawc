nawc-site.config probe

A concrete example of the nawc-site.config.ts shape a notebook author would write. Used as a probe for [[tickets/product-website]].

The shape

The notebook author exports a default config with two fields:

  • files.match — a regex that selects which notes flow into the function as files.
  • faq — the function called with { prompt, files, history } that returns a ConversationTree.

The tree is recursive: question nodes are multiple-choice questions (asked via the question tool), each answer leads to a child node, and answer leaves are emitted as the final canned response. The provider walks the tree by asking each question and following the chosen branch.

Example nawc-site.config.ts

In a real notebook this file lives at the notebook root. It imports defineStaticSiteConfig from @nawc/site and only writes usage code. The types of every field are inferred from the package's exports.

This file is expected to fail typecheck until [[tickets/agent-question-tool]] and the @nawc/site package itself are implemented. The failure is the signal that the implementation ticket is not done yet.
