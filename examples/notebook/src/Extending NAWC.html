Extending NAWC

Three deliberately small contracts keep editor features, agent harnesses, and source intelligence independent.

Plugins

A server-side plugin has a stable name and a resolvable browser client module. It may describe its custom nodes for metadata and contribute skills. The browser module exports a named client plugin containing Tiptap extensions. During startup, NAWC resolves each client from the notebook project and generates a Vite virtual module that the editor imports.

Core custom elements

  • <interactive>...HTML...</interactive> embeds a self-contained prototype.
  • <ref file="path" /> shows a whole file; syntax, name, and type attributes narrow it.
  • <runnable file="path" syntax="ts" /> adds execution through the selected adapter.

Ref and runnable elements never persist resolved code. Interactive content is persisted as the element's children and reconstructed from the Tiptap node attribute during serialization.

Providers

A provider exposes a name and one async-generator prompt function. It receives the prompt, base working directory, and generated skills directory, then yields thread, message, command, error, and completion events. The server transports these events without depending on a particular harness.

Syntax adapters

A syntax adapter has a canonical name, aliases, and a source resolver. The optional runner returns an argv array rather than executing anything itself. Resolvers receive already-read source plus the element attributes, and return code with one-based start and end lines.

TypeScript

The TypeScript compiler API locates functions, methods, classes, type aliases, interfaces, variables, and enums. Function-valued variables include their enclosing variable statement.

Vitest

The Vitest adapter finds an exact string-literal test title. A selector of type it accepts both it and test; another type matches that call name exactly.
